# Gram Stain AI

Gram 染色した細菌の顕微鏡画像を、**ブラウザの中だけ**で分類する教育・研究用のデモ。
画像はサーバへ送られない。GPU 推論サーバも有償 AI API も使わない。

> **医療用途ではありません。** 本システムは医療機器ではなく、出力は医学的診断を意味しません。
> 診断・治療・患者管理に使用しないでください。

---

## 1. このアプリが答えようとしている問い

「Gram 陽性か陰性かを何%当てられるか」ではない。**その%が何を測っているのか**である。

同じモデル・同じ指標でも、データの割り方を変えると別の問いに答えることになる。
本プロジェクトは一つの数を出して終わりにせず、**三つの物差し**を並べて出す。

| 物差し | 割り方 | 答えている問い |
|---|---|---|
| A 画像単位 | 種の中で group-aware に分割 | この 32 分類群のスライドを見分けられるか |
| B 種ホールドアウト | ある種の全画像を test へ | 学習で見ていない**種**の Gram 反応を当てられるか |
| C 科ホールドアウト | ある科の全種を test へ | 学習で見ていない**科**の Gram 反応を当てられるか |

C を置く理由は実測にある。採用した 32 分類群のうち **11 が Lactobacillaceae 科**である。
種を 1 つ抜いても近縁の 10 が学習側に残るので、**B は「未知の種」を測っているつもりで、
近縁の見覚えを測りうる**。

さらに、Gram 染色は陽性が紫・陰性が桃〜赤に染まる**色の検査**である。
だから**学習を一切しない色相統計だけの分類器**を陽性対照として並べる。
CNN の成績は、この対照との差でしか意味を持たない。

### 測った結果(loop_004)

| | A 画像単位 | B 分類群ホールドアウト | C 科ホールドアウト |
|---|---|---|---|
| **CNN**(MobileNetV3-Small) | 0.9731 [0.9580, 0.9858] | 0.9276 [0.9085, 0.9443] | **0.6942** [0.6577, 0.7329] |
| 色相(R/B 比・**学習なし**) | 0.9714 [0.9593, 0.9824] | 0.9524 [0.9363, 0.9673] | 0.9601 [0.9457, 0.9736] |
| 多数派クラス | 0.4171 | 同左 | 同左 |

macro F1 と 95% 信頼区間。どの行も全 1,966 枚を一度ずつ評価している。

**同じモデル・同じ指標で、測る向きを変えると 0.9731 が 0.6942 になる。**
学習を一切しない色の規則は、同じ操作で 0.9714 から 0.9601 までしか動かない。
CNN が失った差は、Gram 反応の理解ではなく**分類群の見覚え**だった。

判定は [SPEC.md](SPEC.md) §3.4 に**測る前に**書いた二条件へ機械が当てはめている。

- 条件 1(三つの物差しすべてで色の規則を上回る): **不成立**
- 条件 2(色の規則が落ちる分類群で明確に上回る): **成立**
  (`Listeria monocytogenes` 44%→33%、`Porphyromonas gingivalis` 37%→35%、
  `Staphylococcus epidermidis` 14%→2%)

> **CNN は色以外の手がかりを確かに少し使っているが、その手がかりは学習で見た分類群に強く依存する。**
> 全体では色の規則に勝てず、未知の科ではまったく歯が立たない。

出荷モデルの test macro F1 は **1.0**(286 枚)である。正しい手順で出した数だが、
**単独では出さない**。上の表と必ず並べる。詳しくは [reports/cnn.md](reports/cnn.md)。

### 対照は CNN より先に測った

| 対照 | A 画像単位 | B 分類群ホールドアウト | C 科ホールドアウト |
|---|---|---|---|
| **色相(R/B 比・非学習)** | **0.9714** [0.9593, 0.9824] | **0.9524** [0.9363, 0.9673] | **0.9601** [0.9457, 0.9736] |
| キャンバス寸法(画素を見ない) | 0.5300 [0.4956, 0.5637] | 0.5375 [0.5032, 0.5706] | 0.5359 [0.5010, 0.5699] |
| 多数派クラス | 0.4171 [0.4039, 0.4292] | 同左 | 同左 |

macro F1 と 95% 信頼区間。どの物差しでも全 1,966 枚を一度ずつ評価している。

**染まった画素の R/B 比に閾値を一本引くだけで macro F1 0.95 を超える。** 学習は一切していない。
しかも三つの物差しでほとんど動かない —— 色は種の同一性に依らないからである。

つまり **CNN の成績はこの水準と比べて語らなければ意味がない**。
何をもって「CNN が効いた」と言うかは [SPEC.md](SPEC.md) §3.4 に、
**測る前に**書いてある。

詳しい読み方は [reports/controls.md](reports/controls.md) にある。

### 分割

物差し A は 1,390 / 290 / 286 枚(出荷モデル用)と、比較用の group 8 分割。
物差し B は分類群を抜く 8 fold(test 242〜251 枚)、物差し C は科を抜く 6 fold。
各 fold の test には Gram 陽性と陰性の両方が入るようにしてある ——
片方しか無い fold で macro F1 を取ると、存在しないクラスの F1 が 0 として混ざり、
**成績が fold の作り方の産物になる**。

## 3. Features

- Gram 陽性 / 陰性の分類(Stage A)
- 形態(球菌 / 桿菌)の分類(Stage B・典拠で形態が定まる 30 分類群のみ)
- 画像アップロード(JPEG / PNG / WebP・10MB まで)とサンプル画像
- クラス別スコアの表示と、確信度が低いときの注記
- Gram 染色そのものの解説(4 工程と染め分かれの理由)
- モデル / データセット / ライセンスの情報ページ

## 4. Architecture

```text
公開データ(CC BY 4.0)
```

## 5. Dataset

**Bacteria Data for Machine Vision and Digital Biology**(Mendeley Data,
[10.17632/cvkgfzp7ck.1](https://doi.org/10.17632/cvkgfzp7ck.1), CC BY 4.0)

配布元の記載では 33 種 2,722 枚の RGB 画像(Nikon E200・100 倍対物・Gram 染色後)。

**実測は違った**(2026-09-08・`ml/verify_dataset.py`)。

| 項目 | 記載 | 実測 |
|---|---|---|
| zip | — | 34 本 / 3,597,653,809 バイト(うち 1 本は同一内容の重複) |
| 分類群 | 33 | 33 |
| 画像 | 2,722 | **2,094** |
| 一意な画像(SHA-256) | — | **2,028** |

記載と実測が 628 枚違う。記載が結合前後のどちらを指すのか判別できないため、
**本プロジェクトは実測値だけを使う**。

画像の実物には次の性質がある。

- 正方キャンバスに**円形の視野**が内接し、四隅は黒い。アルファチャンネルが円形マスクになっている
- 全 2,094 枚が正方・RGBA。キャンバス幅は 739〜1532 px の 100 通り
- **バイト完全一致の重複が 66 組**。60 組は重複 zip 由来だが、**6 組は同一 zip の中**にある
  (`Enterococcus faecium/24.png` = `25.png` など、連番の隣どうし)

つまり **番号が違うことは中身が違うことを意味しない**。
ファイル名を group ID にして分割すると、同じ画像が train と test の両方に入る。

### 目で見た印象は外れた

loop_001 では貼り合わせを見た印象から「同一視野の近接ショットが多数ある」と書いた。
loop_002 で同一分類群の全 59,539 対を測ると、**同一視野と呼べる対は 3 組しかなかった**。

代わりに別の構造が出た。同一 (分類群, キャンバス寸法) のセルは、1225px を除く 421 セルのうち
**264 セルがちょうど 3 枚**、76% が 3 の倍数である。ただしこれは同一視野ではない ——
セル内の知覚ハッシュ距離は中央値 126 で乱数対と変わらず、目視でも別の視野で、
染色の濃さと背景だけが揃っている。**同じスライドの別視野**と読める。

配布物に撮影セッション ID は無いので、これをスライドの代理として group にまとめている。
代理であって本物ではないこと、1225px の大きなセル(全体の約 4 分の 1)は
まとめられないままであることを、成績と一緒に出す。

取得は `python ml/download_dataset.py`。SHA-256 と取得日を `dataset/metadata/` に記録する。
**画像そのものはリポジトリに入れない。**

### ラベルの出所(循環の禁止)

Gram 反応と形態は画像からではなく**種名から**決まる。その対応表は外部権威に取っている。

- **BacDive**(Leibniz Institute DSMZ・CC BY 4.0)から 33 分類群 × 各最大 100 株を取得
- 権威の生の回答は `dataset/metadata/authority_bacdive.json`、採用後は `labels.json`
- 採用規則(語の正規化・一致率の閾値)はコードとデータの両方に明記してある

実測でわかったこと:

- **門から Gram は決められない。** `Veillonella` は Bacillota 門でありながら Gram 陰性である。
  他の Bacillota はすべて陽性なので、門で決め打つ実装はここだけ静かに間違える
- **フォルダ名の属は現行の属ではない。** `Lactobacillus` 属は 2020 年に分割され、
  データセットの 11 フォルダは現在 5 属にまたがる。フォルダ名を属として切ると物差し C を誤る
- **形態のほうが Gram より合議が割れる。** `Acinetobacter baumannii` は権威 68 株で
  桿菌 59% / 卵形 41%(coccobacillus)。形態ラベルを付けず Stage B から外した

### 採用結果

| 項目 | 実測 |
|---|---|
| 採用した分類群 | 32 / 33 |
| 除外 | `Candida albicans`(真菌。NCBI Taxonomy taxid 5476 の Lineage が Fungi) |
| Gram 陽性 / 陰性 | 23 分類群 / 9 分類群 |
| 典拠の一致率 100% でないもの | `Bifidobacterium spp`(97.1%)、`Fusobacterium`(87.5%) |
| Stage B 対象 | 30 分類群(`Acinetobacter baumannii` と `Porphyromonas gingivalis` を除く) |
| 科の数 | 19(最大は Lactobacillaceae の 11) |

## 7. Model

採用: **MobileNetV3-Small + ImageNet 転移学習**(パラメータ 1,519,906・fp32 6.08 MB)。

当初は ResNet18 を標準候補にしていたが、**実測で外した**。

| 骨格 | fp32 サイズ | CPU 学習速度(実測) |
|---|---|---|
| ResNet18 | 46.8 MB | 17.4 枚/秒 |
| EfficientNet-B0 | 21.2 MB | 16.4 枚/秒 |
| **MobileNetV3-Small(採用)** | **10.2 MB**(2 クラス化後 6.08 MB) | 60.1 枚/秒 |

ResNet18 は**量子化する前から**配信目標 30 MB を超える。目標を動かさず骨格を変えた。

## 8. Training

`python -m ml.train --stage all`。エポック予算は物差し A の val で決め(3 エポック)、
その予算を全 fold に一律に当てる。test は一切見ない。

増補は水平・垂直反転と 90 度回転のみ。**色は振らない** ——
Gram 染色では色調が分類情報そのものだからである。
クラス不均衡(陽性 1,407 / 陰性 559)は損失の重みで補正している。

学習系の陽性対照(G-09)としてラベルを無作為に置換した走行も回した。
macro F1 は 0.4356 [0.4074, 0.4625] で多数派クラス 0.4171 と区間が重なる ——
信号を消せば成績も消える。

## 10. Browser Inference

ONNX Runtime Web(wasm・CPU)を自オリジンから配る。CDN を見に行かない。

### 実ブラウザで測ったこと(2026-09-10)

**利用者と同じ経路**を Playwright に歩かせる ——
サンプルを押す → ブラウザが PNG を復号 → 移植した `resizePIL` → ORT Web → softmax → 画面の%。

```bash
npx next build && node scripts/verify-browser.mjs                        # ローカルの out/
node scripts/verify-browser.mjs https://gram-stain-ai.vercel.app         # 本番
```

**ローカルのビルドを検品しても、本番の検品にはならない。** 配信の設定・圧縮・ヘッダは
本番にしか無く、そこで壊れることがある。だから本番に対する検品を別に持つ。

| 見るもの | 判定 | ローカル | **本番** |
|---|---|---|---|
| 画面の%が Python の ONNX Runtime と一致(G-02) | 差 ≤ 0.05 pt | 10/10(最大 0.043) | **10/10**(最大 0.043) |
| 外部への通信 | 0 件 | 0 件 | **0 件** |
| 1 枚目(モデル取得と初期化を含む) | ≤ 5000 ms | 1052 ms | **1894 ms** |
| 2 枚目以降 | ≤ 2000 ms | 最大 173 ms | **最大 193 ms**(中央 176) |

**縮小は canvas にさせない。** `drawImage` の補間法は仕様で定められておらず、
ブラウザによって画素が変わる。学習時は PIL で縮小しているので、
そのまま使うと**学習時と違う画像**をモデルに見せることになる。
PIL の縮小を移植した実装(先行プロジェクト manazashi-lab が Pillow と bit 一致まで検証済み)を
持ち込み、こちらの期待値でも改めて検算している(サンプル 10 枚で最大差 < 1e-5)。

配信物は 24.2 MB(ORT 14.1 / モデル 6.1 / サンプル 3.1 / アプリ 0.8)。
ORT の wasm は**自オリジンから配り、束の側には複製させない** ——
バンドラに預けると 13 MB が二重に入る(先行プロジェクトの実測)。検査 T-249 が見張る。

### ONNX 変換と二実装照合(G-01)

`python -m ml.export_onnx`。配信物は `public/models/` に置く。

| 項目 | 実測 |
|---|---|
| exporter | torchscript(opset 17)。dynamo は `torch.export.export` で失敗した |
| `model.onnx` | **5.95 MB**(配信目標 30MB 以内) |
| argmax 一致率 | **1.000000**(全 1,966 枚) |
| softmax 確率の最大差 | **1.125e-05**(表示上 0.001 ポイント) |
| 生 logits の最大絶対差(参考) | 1.0133e-04 |

**二実装照合は非循環のオラクルである。** PyTorch と ONNX Runtime は同じ重みを別実装で走らせる。
こちらが期待値を書いているのではなく、片方が壊れれば一致しないという構造で確かめている。
変換は静かに壊れる —— 演算子の解釈違い、精度の落ち、入力の並びの取り違え。
どれも例外を出さずに「それらしい数」を返す。

**このゲートは一度落ちて、引き直した。** 当初は「生 logits の最大絶対差 < 1e-4」と書いており、
実測 1.0133e-4 でわずかに超えた。閾値を下げるのではなく、**閾値の当て方が誤っていた**と判断した ——
logits は有界でないので絶対差の閾値はモデルの確信度に比例し、しかも製品が表示するのは確率である。
経緯と旧規則での結果は [SPEC.md](SPEC.md) §5.1 に残し、検査 T-245 が消えていないことを確かめる。

照合は test だけでなく**全 1,966 枚**で行う。test に無い入力の並びで壊れていても気づけないため。

## 開発

```bash
python ml/download_dataset.py        # 公式 API から取得し SHA-256 を記録
python ml/fetch_label_authority.py   # BacDive から典拠を取得
python ml/build_labels.py            # 採用規則を当てて labels.json を作る
python ml/verify_dataset.py          # 展開せず zip の中身を実測する
python ml/prepare_dataset.py         # 内接正方形の切り出し・group・三つの分割
python ml/inspect_groups.py          # 閾値の較正(まとめすぎ/まとめ足りないを目視)
python -m ml.run_controls            # 陽性対照(CNN より先に測る)
python -m ml.train --stage all       # CNN を三つの物差しで測る
python -m pytest -q                  # 検査
```

`--threads` の既定は 3。この機は並行して別の処理が走ることがあり、
**得られないコア数を渡すと奪い合って比例より遅くなる**。
長い掃引は fold ごとに `ml/checkpoints/fold_preds/` へ保存され、中断しても続きから走る。

進め方と設計の記録は [SPEC.md](SPEC.md) / [TEST_SPEC.md](TEST_SPEC.md)、
ループの実行記録は `logs/loops/` にある。
